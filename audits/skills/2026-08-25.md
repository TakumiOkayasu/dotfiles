# Skill inventory audit - 2026-08-25

Issue: #442

## Goal

Current Claude/Codex models should own ordinary reasoning, task decomposition, debugging, and local design decisions. A skill should remain active only when it adds a project-specific invariant, a concrete tool/data contract, or an unusual workflow that cannot be expressed by normal model behavior without loss.

This audit removes or disables methodology that acts as ceremony rather than evidence.

## Decision rules

Keep a skill implicitly available only when at least one is true:

1. It encodes a project-specific design or safety invariant.
2. It defines a concrete file/tool/runtime contract the model cannot infer safely.
3. It defines an unusual task contract whose success condition differs from ordinary engineering work.
4. Automatic matching is narrow enough that activation is more useful than ordinary model reasoning.

Otherwise prefer one of:

- normal model reasoning
- explicit-only skill invocation
- an existing rule/tool as the canonical source
- deletion when no separate capability remains

## Boundary after the audit

Normal tasks should not emit methodology status lines or activate a skill merely because a prompt contains a broad keyword.

The model may still choose project-specific implicit skills whose descriptions match a genuinely specialized task. Explicit-only skills remain available when the user or a higher-level workflow deliberately asks for that method.

## Follow-up trigger

Do another pruning pass only when one of these is observed:

- two retained skills repeatedly activate for the same responsibility
- a retained implicit skill changes no decisions compared with normal model behavior
- a rule and skill duplicate the same mandatory text
- a runtime adds native functionality that replaces a repository-specific adapter

Do not create a recurring review ritual solely because this audit exists.
