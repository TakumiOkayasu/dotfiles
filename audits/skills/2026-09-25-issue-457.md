# Skill audit - 2026-09-25

Issue: #457. Baseline: repository `main` at the commit recorded by this PR. The user reports that model accuracy has improved, but no model/runtime pair or observed task result was supplied. This is a source audit; it does not measure a model improvement or run A/B executions.

## Decision

**Keep the specialized skills and their current output formats. Revise the two skills whose operational rules manufacture work or turn arbitrary numbers into quality gates.** The output headers, columns, severity labels, and decision words in `bug-hunt` and `test-coverage-guard` are already specified. No new report format is needed. Preserve evidence, independent checking when useful, safety/approval boundaries, and a clear account of unrun checks. Do not retire these skills solely because a model changed.

The August inventory (`audits/skills/2026-08-25.md`) already removed broad methodology hooks and reduced generic skills. The current source still contains the two hard-coded workflows identified in the issue comment. This audit confirms the source-level need to revise them; whether the edits improve real outcomes remains unmeasured.

## Reviewed sources and boundaries

- Canonical material: all 22 `common/skills/*/SKILL.md` files, four `common/commands/*.md` files, the August inventory, `AGENTS.md`, and references relevant to the two candidate skills. The detailed comparison below concerns four assets. The other 20 skills were inventoried for scope and overlap, not subjected to a line-by-line runtime audit.
- Dependency and deployment: `common/skills/bug-hunt/references/review-lenses.md`, `claude/SUBAGENTS.md`, `scripts/generate-ai-assets.py`, `tests/test_port_claude_assets.py`, and the generated Codex skill test paths. `common/` owns the shared content. Do not edit installed or generated views directly.
- Out of scope: inaccessible personal/managed instructions, third-party plugins, production task traces, live activation behavior, token/cost measurement, and unstated model versions. This audit did not invoke the reviewed skills.

## Decisions on the scoped assets

| Asset | Decision | Evidence and exact boundary |
| --- | --- | --- |
| `bug-hunt` | **TRIM** | Keep its unusual explicit premise, proof requirements and existing `確定バグ / 検証内容 / 調査範囲` output, with CRITICAL/HIGH/MEDIUM/LOW. Restrict activation and the minimum-one-bug success condition to an explicit assumption that a real bug exists in the target diff. A request to look for missed bugs or to challenge changed code does not establish that premise. The current trigger includes both and its success gate applies to all. Its four mandatory hypothesis categories, three simultaneous agents, fixed escalation ladder and 8/10 score should be selectable evidence methods, not hard gates; the score can veto an otherwise reproduced defect. Never manufacture a finding to reach one. |
| `test-coverage-guard` | **TRIM** | Preserve `要修正 / 改善推奨 / 問題なし / サマリー` headings and the requirement that a defect in the code actually fails a meaningful test. The current `30 tests and two modules -> three agents`, mock counts 2/5, 50-line snapshots, 80% mutation score, and deletion after three changes in six months are unsupported universal gates. A thought experiment is a proposed mutation, not evidence that a test actually fails. Recommend edits based on contractual behavior, reachable risk, executed mutation results when available, and coverage gaps. Do not require a live DB for every unit test or delete a flaky test before preserving its unique detection value. |
| `deep-review` | **KEEP** | `common/commands/deep-review.md` already varies agent count and review rounds by actual risk. Its BLOCK/WARN/PASS, Human review, Findings and checks-performed/unperformed sections are concrete output and safety contracts. No observed regression supports changing them. |
| `orchestrate` | **KEEP** | `common/skills/orchestrate/SKILL.md` is explicit-only, disclaims universal agent counts, and keeps a useful Goal/Files/Dependencies/Contract/Verification/Side effects ledger. Do not broaden its activation. |

## Why the remaining hard gates are not evidence

- `bug-hunt` says a broad missed-bug review is a trigger while also requiring **at least one** confirmed real bug and treating zero as BLOCK. A clean diff or a partially unavailable environment can therefore force extra exploration and leave a false failure. Its own anti-pattern prohibits invented bugs. This is a static contradiction in scope, not proof that the current model hallucinates.
- Its 8/10 confidence score sums subjective categories even when an executed test already reproduces a contract violation. Reporting the reproduction and counterevidence is more informative than a fixed cutoff.
- `test-coverage-guard` decides worker count from suite size and module count, neither of which measures independent investigation value. Counting mocks or snapshot lines likewise cannot show whether a changed contract is detected. Mutation percentages apply only to executed, classified mutations on a defined scope, with equivalent mutants accounted for.
- Its report format and classification remain useful. Editing those during a workflow reduction would conflate quality assessment and presentation preference.

## Changes to validate in a separate implementation PR

1. Update only `common/skills/bug-hunt/SKILL.md`, its description and any directly inconsistent reference. Route ordinary review to the existing review command. Retain the minimum-one-bug premise only when the user explicitly asserts it. Allow an honest zero-findings result when the premise is not asserted; preserve a clear scope/limitations report.
2. Update only `common/skills/test-coverage-guard/SKILL.md`. Choose independent reviewers when they add coverage, use contract-breaking experiments where feasible, distinguish executed from hypothetical mutations, and drop global counts as verdicts. Preserve all four existing report sections and labels.
3. Add narrow regression checks for activation wording, preserved output headings, and no unconditional agent/score gates. Regenerate assets with `python3 scripts/generate-ai-assets.py --repo .`, inspect the manifest/source mapping, and run the affected asset/installation tests. This audit PR makes no changes to those instructions.

## Controlled comparison before claiming improved quality

Run old and proposed instructions in separate, fresh sessions with the same named model, effort, tools, repository snapshot, diff, and output schema. Include (a) a known bug with a reproducible failing test; (b) a clean or specification-compliant diff; (c) insufficient environment; (d) a deceptive test that passes when a contract breaks; and (e) a change that requires external writing or human approval. Record true defects, false findings, missed defects, evidence accuracy, refusal/approval boundaries, unexecuted checks, output schema compliance, agents, tool calls, elapsed time and tokens. Treat speed and token use as secondary if quality or safety regresses. An unavailable live runner is `not measured`, not a pass.

## Conclusion and current validation

There is enough source evidence to justify a **targeted skill edit**. There is insufficient evidence to attribute the need to a particular model upgrade, to remove the skills, to waive safety gates, or to promise an empirical improvement. The August audit remains the repository-wide inventory; this document records the issue-specific decision. All reviewed instruction assets remain unchanged in this PR.
