# Hallucination Prevention

**「たぶん正しい」で出力禁止。不確実なものは不確実と明示。**

## 入力

- AIが生成しようとしているコード・情報・設定・コマンド

## 出力

- 確認済みの情報のみを含む回答
- 不確実な箇所は `[要確認: <理由>]` で明示

## 処理手順

### ステップ1: コード生成時のチェック

以下を順番に確認し、1つでも「否」なら出力を保留する:

| 確認項目 | 確認方法 |
|----------|----------|
| パッケージは実在するか | 公式レジストリ (PyPI / npm 等) で確認 |
| API/関数/メソッドは実在するか | 公式リファレンスで確認 |
| 引数の数・型・順序は正しいか | 公式リファレンスで確認 |
| 戻り値の型は正しいか (同期/非同期の区別含む) | 公式リファレンスで確認 |
| 属性/プロパティは存在し、読み書き可能か | 公式リファレンスで確認 |
| 非推奨 (Deprecated) ではないか | 公式リファレンスで確認 |
| ユーザー環境のバージョンで利用可能か | バージョン別リリースノートで確認 |

### ステップ2: 情報提供時のチェック

| 確認項目 | 基準 |
|----------|------|
| 出典の信頼性 | 公式ドキュメント > 査読済み論文 > その他 |
| 日付・数値の正確性 | 桁数・単位を含めて検証 |
| URL | 確認できないURLは提示しない (下記注記参照) |

**「確認できない」の定義**: WebFetch / 実行ログで実在確認できない URL を指す。一般に知られた公式ドキュメント / レジストリの**ドメイン root** (例: `nodejs.org`, `docs.github.com`, `npmjs.com`) および**パス断片** (例: `docs.github.com/en/rest/pulls/comments`) は、パッケージ名・API 名と同格の**公知の参照先**として提示してよい。深い具体的 URL (`https://...` フルパス) を提示する場合は `[要確認: 実在確認推奨]` を付ける。コマンド引数中に現れる REST API パス (例: `gh api repos/{owner}/{repo}/pulls/{n}/comments`) は**コマンド仕様の一部**として扱い、URL 提示制限の対象外。

### ステップ3: 設定/コマンドのチェック

| 確認項目 | 確認方法 |
|----------|----------|
| コマンド/オプションは実在するか | `--help` または公式ドキュメントで確認 |
| 設定ファイル名・配置場所・形式は正しいか | 公式ドキュメントで確認 |
| 環境変数名のスペル・大文字小文字は正しいか | 公式ドキュメントで確認 |

### ステップ4: 不確実な場合の対処

**既定の対処**: 不確実な箇所を `[要確認: <理由>]` で明示しつつ出力する (入力/出力節の L12 参照)。以下の 4 項目は `[要確認]` マーカーで扱い切れないケース (誤情報が致命的 / 代替が明確に存在 / 訂正済 等) の追加対処:

1. **出力しない** — 確認できないものは出力しない
2. **代替案を提示** — 確実に存在するものを提案する
3. **確認方法を提示** — ユーザーが自分で確認できるよう手順を案内する
4. **間違いに気づいたら即訂正** — 影響範囲を説明し、正しい情報で置換する

## 使用例

**❌ 禁止 (不確実な情報をそのまま出力)**

```
requests.get(url, timeout=30, retry=3)  # retry引数は存在しない
```

**✅ 正しい対処**

```
# retry引数はrequestsライブラリに存在しません [要確認: 公式ドキュメント参照]
# 代替: urllib3のRetryアダプタを使用してください
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry
```

**❌ 禁止 (曖昧な表現)**

> おそらくこの設定で動作します。

**✅ 正しい対処**

> この設定は公式ドキュメント (URL) で確認済みです。 / この設定は未確認です [要確認: バージョン X.Y のリリースノートで確認してください]。
