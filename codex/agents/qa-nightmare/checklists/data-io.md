# Data I/O (データ入出力)

CSV/Excelインポート・エクスポート、一括操作で壊れるケース。

## パターン一覧

### DI-01: BOM付きUTF-8インポート
- 攻撃: BOM付きUTF-8、BOMなしUTF-8、Shift_JIS、EUC-JP の各エンコーディングでCSVインポート
- 検証: 文字化けなく取り込めるか。エンコーディング自動判定が正しいか
- 壊れ方: 1行目のカラム名にBOMが混入しマッピング失敗、文字化け
- 嫌度: ★★★★★

### DI-02: ヘッダ行のずれ・欠損
- 攻撃: ヘッダなしCSV、ヘッダが2行目にあるCSV、カラム順序が異なるCSV
- 検証: エラーメッセージが適切か。データがずれて取り込まれないか
- 壊れ方: 名前カラムにメールアドレスが入る、サイレントに列ずれ
- 嫌度: ★★★★★

### DI-03: 区切り文字を含むデータ
- 攻撃: カンマを含む値(「株式会社A,B」)、ダブルクォートを含む値、改行を含む値
- 検証: RFC 4180準拠のCSVパースが行われるか
- 壊れ方: 1レコードが2行に分裂、フィールド境界がずれる
- 嫌度: ★★★★☆

### DI-04: 大量データインポート
- 攻撃: 10万行、100万行のCSVインポート
- 検証: タイムアウトしないか。メモリ不足にならないか。途中経過が表示されるか
- 壊れ方: OOM、504タイムアウト、ブラウザフリーズ、中途半端な取り込み
- 嫌度: ★★★★☆

### DI-05: 空ファイル・不正フォーマット
- 攻撃: 0byteファイル、拡張子だけ.csvの画像ファイル、Excelバイナリ(.xls)
- 検証: 適切なエラーメッセージが出るか。500エラーにならないか
- 壊れ方: 無言で0件取り込み成功、サーバーエラー
- 嫌度: ★★★☆☆

### DI-06: インポート途中のエラーハンドリング
- 攻撃: 100行中50行目にバリデーションエラーがあるCSV
- 検証: 全行ロールバックか、エラー行だけスキップか。エラー行の特定が可能か
- 壊れ方: 49行だけ取り込まれ残り51行が消失、どの行がエラーか不明
- 嫌度: ★★★★★

### DI-07: エクスポート時の特殊文字
- 攻撃: DBに `=SUM(A1:A10)` やHTMLタグを含むデータがある状態でCSVエクスポート
- 検証: Excelで開いた際に数式として実行されないか(CSV Injection)
- 壊れ方: エクスポートしたCSVを開くと任意コマンド実行
- 嫌度: ★★★★★

### DI-08: エクスポート中のデータ更新
- 攻撃: 大量データのCSVエクスポート中に対象レコードを更新・削除
- 検証: エクスポート結果が整合するか。スナップショット分離されているか
- 壊れ方: エクスポートCSVに更新前後のデータが混在
- 嫌度: ★★★★☆

### DI-09: 日付・数値のロケール依存
- 攻撃: 日付 `01/02/2025`(MM/DD? DD/MM?)、数値 `1.234`(千区切り? 小数点?)
- 検証: パース規則が明確で一貫しているか。ロケールによる解釈の揺れがないか
- 壊れ方: 1月2日と2月1日を取り違え、1234と1.234を取り違え
- 嫌度: ★★★★★

### DI-10: 重複データのインポート
- 攻撃: 既にDBに存在するレコードを含むCSVを再インポート
- 検証: 重複検出されるか。上書き/スキップ/エラーの選択肢があるか
- 壊れ方: 同一データが2件、主キー違反で全行失敗
- 嫌度: ★★★★☆
