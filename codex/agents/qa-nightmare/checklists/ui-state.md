# UI State (UI状態管理)

画面の状態管理が壊れるケース。ローディング、エラー、権限切替等。

## パターン一覧

### US-01: ローディング状態の脱出不能
- 攻撃: API呼び出しが5xx/タイムアウトで失敗
- 検証: スピナーが消えるか。エラーメッセージが表示されるか。リトライ導線があるか
- 壊れ方: 永遠にスピナーが回り続ける
- スクショ箇所: エラー発生後の画面
- 嫌度: ★★★★★

### US-02: エラー後のフォーム状態
- 攻撃: バリデーションエラー → 修正 → 再送信
- 検証: エラーメッセージが消えるか。入力値が保持されるか。正しいフィールドがハイライトされるか
- 壊れ方: 修正後もエラー表示が残る、入力値が消える
- スクショ箇所: エラー表示時、修正後
- 嫌度: ★★★★☆

### US-03: サーバーエラー後のUI復帰
- 攻撃: 500エラーが返ってきた後に、ブラウザバック → 通常操作
- 検証: UIが正常状態に復帰するか。キャッシュが汚れていないか
- 壊れ方: 前のエラー状態が残って操作不能
- スクショ箇所: エラー画面、復帰後の画面
- 嫌度: ★★★★☆

### US-04: 条件付き表示の連鎖
- 攻撃: セレクトボックスA変更 → フィールドB表示 → B入力 → A変更 → B非表示 → A元に戻す
- 検証: Bの値がクリアされるか残るか。残る場合は意図的か
- 壊れ方: 非表示のフィールド値がそのまま送信される
- スクショ箇所: 各切り替えステップ
- 嫌度: ★★★★☆

### US-05: disabled/readonlyの抜け
- 攻撃: disabled属性のフィールドをDevToolsで有効化して値変更 → 送信
- 検証: サーバー側でもreadonly制約が効いているか
- 壊れ方: 本来変更不可の値が書き換えられる
- スクショ箇所: 改ざん前後
- 嫌度: ★★★★★

### US-06: ページ離脱の未保存警告
- 攻撃: フォーム入力途中でブラウザ閉じ / 別URL遷移 / リロード
- 検証: 「未保存の変更があります」警告が出るか
- 壊れ方: 無警告でデータ消失
- スクショ箇所: 離脱操作時
- 嫌度: ★★★☆☆

### US-07: トースト/通知の重複
- 攻撃: 同じ操作を高速で3回実行
- 検証: トースト通知が3つ重なるか。最新だけ表示か。自動消去されるか
- 壊れ方: トーストが画面を覆い尽くす、古い通知が消えない
- スクショ箇所: 複数通知表示時
- 嫌度: ★★☆☆☆

### US-08: 検索・フィルタの状態保持
- 攻撃: 検索条件入力 → 検索 → 詳細画面 → 戻る
- 検証: 検索条件が保持されているか。ページ番号は保持されるか
- 壊れ方: 検索条件消失、結果が全件に戻る
- スクショ箇所: 戻った後の検索画面
- 嫌度: ★★★☆☆

### US-09: ソート状態の不整合
- 攻撃: カラムAで昇順ソート → カラムBでソート → カラムAのソートアイコン
- 検証: アクティブなソートカラムが正しく表示されるか。アイコンが2つ同時に付かないか
- 壊れ方: 両カラムにソートアイコンが付く、実際のソートと表示が不一致
- スクショ箇所: ソート切り替え時
- 嫌度: ★★★☆☆

### US-10: リアルタイムバリデーションの矛盾
- 攻撃: フィールドAが必須、Bが「Aが入力済みなら必須」の条件付き必須
- 検証: A入力 → B未入力でblur → Aを消す → Bのエラーが消えるか
- 壊れ方: 条件が外れたのにBのエラーが残る
- スクショ箇所: 各ステップのバリデーション表示
- 嫌度: ★★★★☆
