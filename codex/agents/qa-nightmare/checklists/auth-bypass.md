# Auth Bypass (権限の抜け穴)

認証・認可の隙間で本来アクセスできないデータ/操作に到達するケース。

## パターン一覧

### AB-01: URL直打ちでの他人データアクセス
- 攻撃: `/orders/123/edit` の 123 を 124 に変えて他ユーザーのデータにアクセス
- 検証: 403 or 404 が返るか。データが見えないか
- 壊れ方: 他社の受注データが閲覧・編集可能
- 嫌度: ★★★★★

### AB-02: IDの推測可能性
- 攻撃: 連番IDを1ずつインクリメントして総当たり
- 検証: 認可チェックが全エンドポイントで効いているか
- 壊れ方: IDOR(Insecure Direct Object Reference)による情報漏洩
- 嫌度: ★★★★★

### AB-03: 権限変更後のセッション
- 攻撃: 管理者権限でログイン → 別画面で一般ユーザーに降格 → 元画面で管理者操作
- 検証: リアルタイムで権限が反映されるか。キャッシュが残っていないか
- 壊れ方: 降格後も管理者操作が通る
- 嫌度: ★★★★★

### AB-04: 削除済みユーザーのセッション
- 攻撃: ログイン中にアカウントを論理削除 → 操作継続
- 検証: 次のリクエストで強制ログアウトされるか
- 壊れ方: 存在しないユーザーがシステム操作を継続
- 嫌度: ★★★★★

### AB-05: API直叩きによるUI制限回避
- 攻撃: UI上は非表示/disabled のボタンに対応するAPIを直接呼ぶ
- 検証: サーバーサイドでも権限チェックされるか
- 壊れ方: UIでは見えない操作がAPI経由で実行可能
- 嫌度: ★★★★★

### AB-06: HTTPメソッドの変更
- 攻撃: GETで一覧取得するAPIにDELETEを投げる
- 検証: 不正なメソッドが405で弾かれるか
- 壊れ方: 意図しない操作が実行される
- 嫌度: ★★★☆☆

### AB-07: CSRFトークン検証
- 攻撃: 別ドメインからformをPOSTする(CSRFトークンなし)
- 検証: 403で弾かれるか
- 壊れ方: 第三者サイトからのリクエストが通る
- 嫌度: ★★★★☆

### AB-08: マルチテナントのデータ分離
- 攻撃: テナントAのAPIキーでテナントBのデータを参照
- 検証: テナント間のデータが完全に分離されているか
- 壊れ方: 他社のデータが見える
- 嫌度: ★★★★★

### AB-09: ロール階層の抜け
- 攻撃: 「閲覧者」ロールで編集API呼び出し、「部門管理者」で全社データ取得
- 検証: 各ロールの境界が正しく機能するか
- 壊れ方: 権限外の操作が通る
- 嫌度: ★★★★★

### AB-10: ログアウト後のトークン
- 攻撃: ログアウト → 保存していたJWT/セッションIDで再アクセス
- 検証: 無効化されているか
- 壊れ方: ログアウトが実質的に機能しない
- 嫌度: ★★★★☆
