# Grilling

計画/判断/アイデアについて、未解決の分岐が残らなくなるまで人間へ質問する。
回答と途中経過は日本語で書き、固有名詞/コード/API名は原文を保つ。
上流の出典、変更点、ライセンスは [references/upstream.md](references/upstream.md) に置く。

## 判断の分岐と質問の順序

- 対象の目的/範囲/制約/完了条件を既存の会話から取り出す。不足するものは未決定として扱い、決定済みの内容を再質問しない。
- 判断を枝として整理し、枝ごとに決定内容、根拠、前提となる枝、状態を持つ。状態は `未決定` / `決定済み` / `調査待ち` / `対象外` とする。
- 前提の枝がすべて決定済みの質問をfrontierと呼ぶ。独立したfrontierの質問は同じラウンドへまとめる。
- 同じラウンドの未回答の質問に依存する質問は、次のラウンド以降へ送る。未回答を推奨案で埋めない。
- 人間の回答で枝を更新し、frontierを再計算する。訂正で前提が変わった場合は、影響する決定を未決定に戻す。
- 対象範囲の判断に必要な枝だけを扱う。質問数/ラウンド数/モデル名を固定せず、架空の選択肢や将来の機能を増やさない。

## 事実の調査

事実は利用可能な一次ソース/コード/実行結果で調べ、人間には判断を求める。
自分で取得できる情報の調査を人間へ転嫁しない。
独立した調査には、利用可能なら新しい文脈のsubagentを使う。
subagentを利用できない環境では、同じ調査を自分で行う。

進行中の調査は未解決の前提として扱い、その結果に依存しない質問を先に出す。
取得できない事実は `[要確認: <不足情報と理由>]` とし、その事実が必要な枝だけを調査待ちにする。
確認済みの事実と仮定を分け、アクセスできない個人の事情や意向だけを人間へ聞く。
回答/証拠が増えないまま、同じ調査や質問を繰り返さない。

## 各ラウンドの出力

まず次の途中経過を示す。
初回は既知の内容を記入し、項目がなければ `なし` と書く。
以降は変更があった枝と、今回の質問に必要な前提に絞る。

```markdown
## 途中経過

- 目的/範囲:
- 決定済み: <枝ID、内容、確認した人間の回答>
- 未決定: <枝ID、判断内容、依存する枝>
- 根拠: <判断に必要な確認済み事実と出典>
- 仮定/調査待ち: <未確認の内容、理由、影響する枝>

## 今回の質問

Q<番号> - <質問タイトル>
<前提が解決している判断を1つ尋ねる。はいで推奨案を採用できる文にする。>

- 推奨: <案と理由>
- 比較: <実在する他案との差、採用で得るもの/失うもの>

---

<独立した質問があれば同じ形式で続ける>

途中経過の新規/変更分は、この認識でよいですか?
訂正があれば該当する枝を知らせてください。
各質問への回答を待ちます。
```

質問番号は対話全体で一意にし、回答を対応する枝へ記録する。
途中経過の承認と個別の判断を、1つの質問に詰め込まない。
途中経過の新規/変更分は明示的に確認し、既に確認済みの決定に再承認を求めない。
途中経過そのものに未確認の解釈があれば、それを先に質問し、その解釈に依存する質問を次のラウンドへ送る。

質問を出したら停止し、人間の回答を待つ。
`はい` は直前の提示案への回答としてだけ扱い、複数の質問がある場合は、どの質問に答えたか明確な範囲だけを決定済みにする。
無回答/時間経過/曖昧な反応を承認として扱わない。

## 送信前の品質確認

各モデルは、送信前に次の欠落を直す。

- 決定済みの内容は、人間の回答または既存の明示的な決定に結び付いているか。
- 根拠と仮定が区別され、取得できなかった事実が要確認と表示されているか。
- 各質問の前提は解決済みで、同じラウンドの回答を先取りしていないか。
- 各質問に推奨理由と選択による違いがあり、人間が判断できるか。
- 途中経過の訂正と回答を待つ位置が明確か。

この確認は出力の欠落を減らす共通基準であり、モデル間の判断精度や同一品質を保証しない。
不足を解消できなければ、その理由と未解決の枝を示す。

## 最終確認

frontierが空でも、対象範囲に未決定/調査待ちの枝があれば完了としない。
人間が対象外と決めた枝は、その判断と理由を残す。
対象範囲の枝がすべて解決したら、各ラウンドの形式から次の最終確認へ切り替える。

```markdown
## 共有理解の確認

- 目的/範囲:
- 決定: <枝ごとの内容と理由>
- 対象外: <明示的に除外した内容と理由。なければ、なし>
- 未解決: なし
- 次の作業: <合意した内容から導かれる作業>

この決定内容で共有理解に達したとして、対話を完了してよいですか?
```

最終確認への回答を待ち、訂正があれば影響する枝の質問へ戻る。
共有理解の確認は、実装/外部書き込み/破壊的操作の実行許可とは分ける。
次の作業は、この対話または既存の依頼で許可された範囲だけを実行する。
