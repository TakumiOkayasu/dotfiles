# 語より先に指示対象を確認する

設計・命名・説明では、名前から対象を逆算せず、まず何を指しているかを確認する。

## 原則

- ユーザーが使った語と既存domain用語を優先する。
- 新しい語を導入する場合、その語が指す具体対象と役割を説明できること。
- 状態、事象、値、記録、責務など異なるものを、便利な1語へまとめて意味を曖昧にしない。
- 指示対象が曖昧なら、本文やコードを増やす前に一次情報・既存contract・ユーザーの表現から解消する。
- 曖昧さが解消できない場合は未確認事項として残し、推測で仕様化しない。

## Referent table

対応関係が複雑で、表にすることで実際に判断しやすくなる場合だけ `semantic-generation` skillを明示的に使用してよい。

通常の文書作成、命名、設計ではreferent tableを必須にしない。別fileへの保存、hash記録、本文より先に提出したことの証明も要求しない。

## 禁止事項

- 造語を置いてから、その語に合う対象や仕様を後付けする
- userの用語を根拠なく言い換える
- 対応表や中間成果物の作成自体を目的化する
- 曖昧さがない短文や既存名の再利用へ追加workflowを強制する
