# Domain Specific (ドメイン固有 - 製造業)

生産管理・製造業特有のビジネスロジックで壊れるケース。

## パターン一覧

### DS-01: ロット番号の桁あふれ
- 攻撃: ロット番号が設計上限(例: 999999)に達した状態で新規採番
- 検証: エラーハンドリングされるか。桁あふれで0に戻らないか
- 壊れ方: ロット重複、採番エラーで生産停止
- 嫌度: ★★★★★

### DS-02: 工程間数量不整合
- 攻撃: 投入100個 → 産出102個(物理的にありえない増加)を入力
- 検証: バリデーションで弾かれるか。歩留まり計算が100%超にならないか
- 壊れ方: 在庫が実態と乖離、棚卸差異
- 嫌度: ★★★★★

### DS-03: マスタ変更後の過去データ表示
- 攻撃: 品番マスタを改定(旧品番→新品番) → 改定前の受注を表示
- 検証: 過去受注は旧品番で表示されるか。新規受注は新品番のみ選択可か
- 壊れ方: 過去の受注が新品番で表示される(履歴改竄)
- 嫌度: ★★★★★

### DS-04: 単位変換の丸め
- 攻撃: kg → g 変換で 0.001kg (= 1g) → 再度 g → kg で 0.001kg に戻るか
- 検証: 往復変換で値が一致するか。小数点以下の丸めルールが統一されているか
- 壊れ方: 変換のたびに値がドリフト、出荷数量と受注数量が微妙に不一致
- 嫌度: ★★★★☆

### DS-05: BOM(部品表)の循環参照
- 攻撃: 製品A → 部品B → 部品C → 製品A という循環BOMを登録
- 検証: 循環検出して弾くか。所要量計算が無限ループしないか
- 壊れ方: スタックオーバーフロー、サーバーハング
- 嫌度: ★★★★★

### DS-06: 在庫のマイナス
- 攻撃: 在庫10個の状態で15個の出荷指示
- 検証: マイナス在庫を許容する設定の場合の表示。許容しない場合のバリデーション
- 壊れ方: マイナス在庫が計算に入り後続の所要量計算が狂う
- 嫌度: ★★★★☆

### DS-07: 有効日付範囲のマスタ
- 攻撃: 単価マスタの有効開始日=2025/04/01、有効終了日=2025/03/31(逆転)で登録
- 検証: 日付逆転が弾かれるか。有効期間の隙間(3/31終了 → 4/2開始)で注文した場合
- 壊れ方: 単価取得できずエラー、または意図しない旧単価適用
- 嫌度: ★★★★☆

### DS-08: 工程飛ばし
- 攻撃: 工程1→2→3の順序で、工程1完了後に工程3の実績を登録
- 検証: 工程順序が強制されるか。飛ばし可否の設定が正しく効くか
- 壊れ方: 中間工程の実績がないまま完成報告
- 嫌度: ★★★★☆

### DS-09: 端数処理ルールの混在
- 攻撃: 消費税計算で明細ごと四捨五入 vs 合計後四捨五入の結果比較
- 検証: 請求書の合計が明細合計と一致するか
- 壊れ方: 1円単位のずれで経理から差し戻し
- 嫌度: ★★★★☆

### DS-10: 取消・赤伝処理
- 攻撃: 出荷済み受注を取消 → 赤伝(マイナス伝票)発行 → 在庫戻し
- 検証: 在庫が正しく復元されるか。売上集計からマイナスされるか。二重取消防止
- 壊れ方: 在庫が戻らない、売上が二重マイナス
- 嫌度: ★★★★★
