# State Transition (状態遷移の穴)

正常フローでは通らない遷移パスで壊れるケース。

## パターン一覧

### ST-01: 逆方向遷移
- 攻撃: 承認済み → 下書きに戻す → 再承認 → 却下 → 再編集 → 再承認
- 検証: 各状態遷移後にDB状態・画面表示が正しいか。履歴が正確か
- 壊れ方: 状態フラグが中途半端な値になる
- 嫌度: ★★★★★

### ST-02: 同一ステータスへの多重遷移
- 攻撃: 「承認」ボタンを2回連続クリック(1回目の応答前に2回目)
- 検証: 状態が1回だけ遷移するか。履歴が2件にならないか
- 壊れ方: 承認通知が2通飛ぶ、ポイント二重付与
- 嫌度: ★★★★★

### ST-03: ブラウザバックからの再遷移
- 攻撃: 確認画面で「送信」→ 完了画面 → ブラウザバック → 「送信」
- 検証: 二重登録されないか。PRG(Post/Redirect/Get)パターンが機能するか
- 壊れ方: 同一内容のレコードが2件作成される
- 嫌度: ★★★★★

### ST-04: 削除済みレコードへの操作
- 攻撃: 一覧画面表示 → 別タブでレコード削除 → 元タブで「編集」クリック
- 検証: 適切なエラーが出るか。500エラーにならないか
- 壊れ方: NullReferenceException、空の編集画面
- 嫌度: ★★★★☆

### ST-05: 途中離脱と再開
- 攻撃: ウィザード形式の3画面目で離脱 → 直接1画面目にアクセス
- 検証: 中間状態のデータが残っていないか。セッションはクリアされるか
- 壊れ方: 前回の入力途中データが混在
- 嫌度: ★★★☆☆

### ST-06: 有効期限切れ後の操作
- 攻撃: クーポン・キャンペーン等の有効期限を過ぎた後に適用操作
- 検証: 期限切れが正しく弾かれるか。既に適用済みのものは維持されるか
- 壊れ方: 期限切れクーポンが使える、適用済みが取り消される
- 嫌度: ★★★★☆

### ST-07: バッチ処理中の手動操作
- 攻撃: 月次集計バッチ実行中に対象レコードを手動更新
- 検証: バッチ結果が整合するか。ロックが効くか
- 壊れ方: 集計途中のデータが混在、合計不一致
- 嫌度: ★★★★★

### ST-08: 並行する状態遷移
- 攻撃: 同一レコードをユーザーAが「承認」、同時にユーザーBが「却下」
- 検証: 楽観ロック or 排他制御が機能するか
- 壊れ方: 承認と却下の両方が成功、最後に書いた方が勝つ
- 嫌度: ★★★★★
