# Failure Logging

## 概要

**失敗したら記録。新しいアプローチの前に履歴を読む。**

エラー・アプローチ失敗を蓄積し、同じ失敗を繰り返さない。

---

## 入出力

| 項目 | 内容 |
|------|------|
| **入力** | エラー内容・試したコマンド・失敗したアプローチ |
| **出力** | `claude_tmp/failure_log/[連番範囲]-fail.md` への追記 |

---

## 処理手順

### 1. 記録タイミングの判定

以下に該当する場合、ただちに記録へ進む:

- コマンドがエラーになった
- 試したアプローチがうまくいかなかった
- 同じ問題で2回以上つまずいた

### 2. 既存ログの確認

```bash
ls claude_tmp/failure_log/
cat claude_tmp/failure_log/[最新ファイル]
```

- 最新の連番を確認する
- 同一問題の過去ログがあれば原因・解決策を再確認する

### 3. ログディレクトリの作成 (初回のみ)

```bash
mkdir -p claude_tmp/failure_log
```

### 4. 記録フォーマットで追記

`claude_tmp/failure_log/[連番範囲]-fail.md` に追記:

```markdown
## [連番]
- 何をしようとしたか:
- 試した手法/コマンド:
- 結果 (エラー内容):
- 原因 (明確な場合のみ):
```

### 5. 解決時の更新

該当エントリに追記:

```markdown
## [連番]
- 何をしようとしたか: ...
- 試した手法/コマンド: ...
- 結果 (エラー内容): ...
- 原因: ...
- ✅ 解決済み: [解決方法を具体的に記載]
```

---

## 参照タイミング

- 新しいアプローチを試す**前**
- 同じ問題に再度取り組む時
- `/compact` 後 (コンテキストリセットのため)

---

## ファイル管理

- 100件ごとにファイルを分割: `1-100-fail.md`, `101-200-fail.md`
- 過去ファイルも参照する (失敗DBとして蓄積)

---

## 使用例

```
# 例1: dockerコマンドでエラー発生
→ claude_tmp/failure_log/1-100-fail.md に追記
## 3
- 何をしようとしたか: docker compose run でテスト実行
- 試した手法/コマンド: docker compose run test
- 結果 (エラー内容): service "test" not found
- 原因: compose.yaml に test サービス未定義
```

```
# 例2: 新アプローチ試行前
→ cat claude_tmp/failure_log/1-100-fail.md で過去ログ確認
→ 同一手法が失敗済みであれば別アプローチを選択
```

---

## 禁止事項

- 失敗を記録せずに次へ進む
- 履歴を読まずに同じアプローチを試す
- 過去の失敗DBを無視する
