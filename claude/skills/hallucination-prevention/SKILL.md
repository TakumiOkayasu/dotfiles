# Hallucination Prevention

## 鉄則

**「たぶん正しい」で出力禁止。不確実なものは不確実と明示。**

---

## 1. コード生成時

### パッケージ/API存在確認

- [ ] パッケージは実在するか? (公式レジストリで確認)
- [ ] API/関数/メソッドは実在するか? (公式リファレンスで確認)
- [ ] 引数の数・型・順序は正しいか?
- [ ] 戻り値の型は正しいか? (同期/非同期の区別含む)
- [ ] 属性/プロパティは存在し、読み書き可能か?
- [ ] 非推奨(Deprecated)ではないか?
- [ ] ユーザー環境のバージョンで利用可能か?

**よくある間違い:**
- plausibleだが存在しないパッケージ名/関数名を生成 (~20%)
- 別ライブラリの関数と混同
- 新バージョンのAPIを古い環境で使用

---

## 2. 情報提供時

- [ ] 出典は信頼できるか? (公式ドキュメント > 査読済み論文 > その他)
- [ ] 日付・数値は正確か? (桁数・単位含む)
- [ ] URLは確認済みか? → 確認できないURLは提示しない

---

## 3. 設定/コマンド

- [ ] コマンド/オプションは実在するか? (`--help`/公式ドキュメントで確認)
- [ ] 設定ファイル名・配置場所・形式は正しいか?
- [ ] 環境変数名のスペル・大文字小文字は正しいか?

---

## 4. 不確実な場合

```
⚠️ 以下の点について確認が必要です:

【存在確認】
- `{名前}` の存在を確認できていません
  → 確認方法: {公式ドキュメントURL}
  → 代替案: {確実に存在するAPI}

【鮮度チェック】
- `{API名}` は非推奨の可能性があります
  → 確認方法: {最新ドキュメントURL}
```

**原則:** 確認できないものは出力しない or 確認方法を添える。

---

## 5. 違反時の対応

1. **出力しない** — 確認できないものは出力しない
2. **代替案を提示** — 確実に存在するものを提案
3. **確認方法を提示** — ユーザーが自分で確認できるよう案内
4. **間違いに気づいたら即訂正** — 影響範囲を説明し正しい情報で置換
