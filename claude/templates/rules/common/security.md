# セキュリティ

## 入力処理

- ユーザー入力は必ずバリデーション (ホワイトリスト方式)
- 入力長の上限を設定
- SQLは必ずパラメータ化クエリ (文字列結合禁止)
- パストラバーサル防止: ユーザー入力由来のパスを正規化・検証
- リダイレクト先URLのホワイトリスト検証

## 認証・認可

- 認証チェックは全エンドポイントで実施
- 認可は機能単位で最小権限を適用
- セッションIDは推測不可能な値を使用
- パスワードはbcrypt/argon2でハッシュ化 (平文・MD5/SHA禁止)

## 機密情報

- 秘密情報はハードコード禁止 (環境変数経由)
- ログに認証情報・個人情報を出力しない
- エラーレスポンスにスタックトレース・内部情報を含めない
- HTTPレスポンスヘッダーでサーバー情報を隠蔽

## 依存・通信

- 依存パッケージの脆弱性を定期確認
- 外部通信はTLS必須
- CORS設定は必要最小限のオリジンのみ許可
- CSRFトークンを使用

## ファイルアップロード

- アップロードファイルのMIMEタイプと拡張子を検証
- ファイルサイズの上限を設定
- アップロード先はWebルート外に配置

## レート制限

- APIエンドポイントにレート制限を設定
- 認証試行回数を制限 (アカウントロックアウト)

## 禁止事項

- `eval()` / 動的コード実行
- デシリアライズに信頼できないデータを渡す
- ユーザー入力をコマンド文字列に展開 (OSコマンドインジェクション)
- 本番環境でのデバッグモード有効化
