# セキュリティ

## 概要

コーディング時に適用するセキュリティルール集。実装・レビュー・修正の全フェーズで参照する。

## 入力

- コードレビュー対象のソースコード、または実装要件

## 出力

- セキュリティルールに準拠したコード
- 違反箇所がある場合: 違反内容と修正案の一覧

## 処理手順

### Step 1: 入力処理の検証

- [ ] ユーザー入力にホワイトリスト方式のバリデーションを実施しているか
- [ ] 入力長の上限を設定しているか
- [ ] SQLはパラメータ化クエリを使用しているか（文字列結合は違反）
- [ ] ファイルパスはユーザー入力由来の場合、正規化・ホワイトリスト検証しているか
- [ ] リダイレクト先URLをホワイトリストで検証しているか

### Step 2: 認証・認可の検証

- [ ] 全エンドポイントで認証チェックを実施しているか
- [ ] 認可は機能単位・最小権限で適用しているか
- [ ] セッションIDは暗号論的に安全な乱数を使用しているか
- [ ] パスワードはbcryptまたはargon2でハッシュ化しているか（平文・MD5・SHA-1は違反）

### Step 3: 機密情報の検証

- [ ] 秘密情報（APIキー・パスワード等）がハードコードされていないか（環境変数経由が必須）
- [ ] ログに認証情報・個人情報を出力していないか
- [ ] エラーレスポンスにスタックトレース・内部情報を含めていないか
- [ ] HTTPレスポンスヘッダーでサーバーバージョン等を隠蔽しているか

### Step 4: 依存・通信の検証

- [ ] 依存パッケージの既知脆弱性を確認しているか（`npm audit` / `pip-audit` 等を使用）
- [ ] 外部通信はTLS（HTTPS）を使用しているか
- [ ] CORS設定は必要最小限のオリジンのみ許可しているか
- [ ] 状態変更リクエストにCSRFトークンを使用しているか

### Step 5: ファイルアップロードの検証

- [ ] MIMEタイプと拡張子を両方検証しているか
- [ ] ファイルサイズの上限を設定しているか
- [ ] アップロード先がWebルート外のディレクトリであるか

### Step 6: レート制限の検証

- [ ] APIエンドポイントにレート制限を設定しているか
- [ ] 認証試行回数を制限しているか（アカウントロックアウト実装）

## 禁止事項（即座に修正）

| 違反パターン | 理由 |
|------------|------|
| `eval()` / 動的コード実行 | 任意コード実行のリスク |
| 信頼できないデータのデシリアライズ | オブジェクトインジェクションのリスク |
| ユーザー入力をコマンド文字列に展開 | OSコマンドインジェクションのリスク |
| 本番環境でのデバッグモード有効化 | 内部情報漏洩のリスク |

## 使用例

```
# レビュー依頼
「以下のコードにセキュリティルールを適用してレビューしてください: [コード]」

# 実装依頼
「ユーザー登録APIをセキュリティルールに準拠して実装してください」
```
