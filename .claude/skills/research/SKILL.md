# Research(Perplexity検索)

## 📋 実行前チェック(必須)

### このスキルを使うべきか?
- [ ] 最新の情報が必要?(2024年以降の変更など)
- [ ] 公式ドキュメントだけでは不十分?
- [ ] 複数の情報源を比較したい?
- [ ] 技術選定のための調査が必要?

### 前提条件
- [ ] `PERPLEXITY_API_KEY` が設定されているか?
- [ ] `research` コマンドが使用可能か?
- [ ] 調査内容を具体的に言語化できているか?

### 禁止事項の確認
- [ ] 公式ドキュメントで解決できる内容ではないか?
- [ ] 既にローカルに情報があるのではないか?
- [ ] 漠然とした調査依頼になっていないか?

---

## 🚨 鉄則

**公式ドキュメントを先に確認。researchは補完手段。**

## トリガー

### 手動トリガー
- ユーザーから「調べて」「調査して」「最新情報を確認して」
- 技術選定で複数の選択肢を比較したい時
- エラーの解決策を外部から探したい時

### 自動トリガー(推奨シナリオ)
- 公式ドキュメントで解決できなかった時
- ライブラリのバージョン互換性を確認したい時
- セキュリティ脆弱性の最新情報を確認したい時

---

## 実行方法

### 基本

```bash
# 軽い検索(デフォルト、高速、~$0.01-0.05/query)
research "TypeScript 5.4 新機能"

# Deep Research(徹底調査、~$0.15-0.50/query)
research -d "2024年のRust非同期ランタイムの比較"

# パイプで入力
cat error.log | research "このエラーの原因は?"
```

### オプション

```bash
# モデル指定
research -m deep "徹底調査内容"
research -m sonar "軽い検索"
research -m reasoning "推論重視の検索"

# 引用元を非表示
research -q "質問"
```

## 調査テンプレート

### 技術調査

```bash
research "
[調査対象]: React Server Components
[知りたいこと]:
- 2024年時点のベストプラクティス
- 既知の問題点と回避策
- Next.js以外での利用方法
"
```

### エラー調査

```bash
research "
[エラー]: ECONNREFUSED 127.0.0.1:5432
[環境]: Docker Compose, PostgreSQL 16
[試したこと]: コンテナ再起動、ポート確認
"
```

### 比較調査(Deep推奨)

```bash
research -d "
[比較対象]: Prisma vs Drizzle vs TypeORM
[観点]:
- TypeScript型安全性
- マイグレーション機能
- パフォーマンス
- 2024年のアクティブ度
"
```

## 結果の活用

1. **引用元を確認** - 信頼できるソースか確認
2. **日付を確認** - 古い情報でないか確認
3. **公式と照合** - 重要な情報は公式ドキュメントと照合
4. **記録** - 重要な調査結果は `claude_tmp/` に保存

---

## 🚫 禁止事項まとめ

- 公式ドキュメントを確認せずに調査
- 漠然とした調査依頼(「○○について調べて」だけ)
- Deep Researchの乱用(コスト注意)
- 調査結果の鵜呑み(必ず検証)
