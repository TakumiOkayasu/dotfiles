### 📝 observer note

- SKILL.md 116 行は全スキルで最小クラス（failure-logging 107 / systematic-debugging 109 に次ぐ）。簡潔さがむしろ「暗黙の仕様」を subagent に補完させる傾向
- テンプレが 6 セクションで厳格 → 出力形式の強制度が高い → 裁量補完は「内容」面で発生しやすい（形式は固い）
- 「発動しない条件」と禁止事項で発動抑止が二重化されており、シナリオC/D で抑止側の挙動観察が重要
- interface-first-design の iter 0 でも同種の「隣接スキル境界明示不足」が指摘されていた（IFD-0-3）→ refactoring iter 2 と同じ「委譲先」節追加パターンが有効候補
