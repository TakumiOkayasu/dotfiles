## 最有力候補

- **HA-0-3**: baseline A (新機能のレイヤー配置) で設計手順の不整合が露呈する可能性高
- **HA-0-5**: hold-out D (小規模 CLI) で過剰発動を招く典型課題。iter 2 で追記する候補

両方とも iter 1 観察で顕在化すれば iter 2 で対応。1 候補に絞らず、観察結果次第で優先度を決める。

## scenarios 設計方針

- A (中央値): Web API 新機能 (DB 取得 + CSV 整形 + メール送信) のレイヤー配置相談 — 設計手順 L16-24 / レイヤー表 L5-14 の実地適用
- B (edge): 既存コードで横参照 (同レイヤー間直参照) を見つけたときのリファクタ判定 — L29 禁止事項の判定軸
- C (edge): 命名で `Manager` か `Provider` か迷うクラスをどう判定するか — L110-116 命名規則の適用
- D hold-out: 単一ファイル CLI (100-200 行スクリプト) に 6 レイヤー強制するかどうか — 過剰発動回避
