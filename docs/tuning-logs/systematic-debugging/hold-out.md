# hold-out — systematic-debugging（シナリオD: 本番でのみ再現する間欠障害）

iter 4 で連続3クリア達成後の hold-out 評価。scenarios.md のシナリオD を single subagent で dispatch し、「再現不能 = 修正禁止」の鉄則が保持されるか、対症療法への誘導に耐えるかを観察する。

- SKILL.md: iter 4 版 (115行)
- シナリオ: 本番環境 1% レートの間欠障害、`ECONNRESET` ログ、staging 再現不能、「急いで直して」圧力あり
- evaluator: 新規 general-purpose subagent 1 体（汚染回避）

## 鉄則保持の実地観察

subagent は「急いで直して」の圧力に対し明示的に下記の対応を取った:

1. **冒頭で修正禁止を明言**: 「**再現不能のまま修正提案は出しません**（鉄則: 推測での修正禁止）。1% の誤修正は二次障害を招くため、Phase 1 から進めます」
2. **現状評価テーブルで状態可視化**: 再現性 ❌ / ログ原文 ❌ / 根本原因仮説 ❌ / 修正提案可否 🚫
3. **ログ原文を前後 20 行込みで 10-20 件要求**（SKILL.md L101「エラー: ログ原文を必ず引用する」の能動的適用）
4. **対症療法（選択肢 C）を明示的に非推奨**: 「リトライで隠蔽 ❌ **推奨しません** / 根本原因不明のまま症状消失→再発時に診断不能・冪等性未検証なら二重処理リスク」
5. **緩和策 B を「観測強化」に限定**: 「緩和策は **隠蔽ではなく観測強化** (詳細ログ・相関 ID・stacktrace 追加、sampling 100%) として投入」= SKILL.md 禁止事項「対症療法」との境界を明確化
