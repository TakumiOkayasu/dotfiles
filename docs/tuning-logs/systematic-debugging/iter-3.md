### B-3 解消の実地観察

iter 1・iter 2 で subagent B が要件6 △ 評価の根拠としていた「failure-logging 連携手順の不在」は、iter 3 では **subagent B/A/C の全員が自然に言及** した:

- **subagent B**: 「今回の 2 回の失敗は `failure-logging` スキルで記録対象とします（同じ失敗を繰り返さないため）。3 回目に進む前に、上記 [要確認] 回答を受けて Phase 1（再現）→ Phase 2（境界トレース）をやり直し」
- **subagent A**: 「記録は `failure-logging` スキルのテンプレートで保持します」（失敗履歴でなく初回デバッグの段階でも予防的に言及）
- **subagent C**: 「failure-logging スキル発動の要否: 現時点では「まだ失敗0回」のため未発動、2回失敗時に発動予定」（再現未達の段階で「未発動」状態を正しく認識）

iter 2 で「connected を暗黙に期待するが明文なし」だった状態が、iter 3 では「明示された連携手順として消化」されている。特に subagent C が「まだ失敗0回 = 未発動」と段階条件まで読み取っている点が、修正文「いずれの段階でも」の効果。
