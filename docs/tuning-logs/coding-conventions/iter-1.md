## 分析

### 最重要: 不明瞭点の分布

iter 0 で予測した懸念 3 点が iter 1 で実害として浮上:

| iter 0 懸念 | iter 1 結果 | シナリオ |
|---|---|---|
| CC-0-3 (L106 空配列 vs null) | CC-1-A-1 で浮上 | A |
| CC-0-4 (L208-209 React 例外境界) | CC-1-B-1 で浮上 | B |
| CC-0-5 (L149 try/catch 配置) | CC-1-C-1 で浮上 | C |

iter 0 CC-0-1 (14 トピック優先順位欠落) は iter 1 で **実害なし**: 3 subagent とも critical 違反を先に、軽微事項を後に、という優先順位を裁量で適切化。

iter 0 CC-0-2 (硬い数値基準) も iter 1 で **実害なし**: subagent A はマジックナンバー 1000 を `MAX_ITEMS` 定数化、ネスト平坦化は機械的ではなく早期リターン文脈で自然に適用。

### iter 2 テーマ選定の優先度

3 シナリオすべてで独立に「選択基準なし」が浮上。どれを先に解消するかの優先度:

| 候補 | シナリオ分布 | 影響度 | 修正容易度 |
|---|:---:|:---:|:---:|
| CC-1-C-1 (try/catch 配置) | C のみ | 高 (async 伴う全実装に波及) | 1 行追記で済む |
| CC-1-A-1 (null vs 空配列) | A のみ | 中 (返却設計限定) | 1 行追記で済む |
| CC-1-B-1 (React 例外境界) | B のみ | 中 (React 文脈限定) | 数行追記必要 |

**選定**: **CC-1-C-1 (try/catch 配置基準)** を iter 2 で最小修正。理由:
1. 影響範囲が最も広い (エラーハンドリング + 非同期 + ログ すべてに関わる)
2. 1 行追記で済む
3. 裁量補完コスト (subagent の迷い) を構造的に削減

CC-1-A-1 / CC-1-B-1 は iter 3 以降に回す (1 テーマ原則)。

## iter 2 修正案

**対象**: L149 「エラー伝播」行

**修正前**:
```
| エラー伝播 | `try/catch` で捕捉するか、呼出側に任せる (握り潰し禁止) |
```

**修正後**:
```
| エラー伝播 | `try/catch` で捕捉するか、呼出側に任せる (握り潰し禁止)。**判定**: 関数が意味のある回復・文脈付与・ログ出力を行えるなら捕捉、できないなら上位へ伝播 |
```

**狙い**: L149 の曖昧性を解消し、subagent が「どちらを選ぶか」で迷う裁量コストを構造的に削減。

**予想波及**:
- シナリオ C で再評価時、try/catch 配置の根拠が rule 引用のみで成立 (裁量補完なし)
- 他シナリオ (async を含む実装一般) への同様の効果
