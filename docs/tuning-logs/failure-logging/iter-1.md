## 最重要選定（iter 2 テーマ）

**FL-1-B-2「出力形式 `[件数]` の定義未規定」** を選定する。

### 選定理由

| 観点 | 判定 |
|---|---|
| 構造的曖昧か | ○ 「件数」は 3 通りに解釈可能（全ヒット / 未解決のみ / 除外手法数） |
| 実害顕在度 | ○ シナリオB の subagent 報告 + empirical 側 EP-1-B-1 の二重指摘。毎回出力する形式なので普遍的 |
| 最小修正可能か | ○ SKILL.md L93-95「出力形式」節に定義を 1 行追記で解消 |
| 因果が明瞭か | ○ 「軸名」ではなく「判定文言」を直接修正（empirical L79-81 の「ゼロ振れ回避」原則に合致） |
| 波及上振れの可能性 | ○ EP-1-B-1 も同時解消（上振れパターン） |

### 他候補を見送った理由

| 候補 | 見送り理由 |
|---|---|
| FL-1-A-1（0 件時分岐） | 発生頻度が低く、今回シナリオでは実害化せず（A は既存 DB の追記のみ、B は 137 件の DB あり）。iter 3+ に温存 |
| FL-1-A-2（原因の「明確性」判定） | 毎記録で発生する普遍的曖昧ではあるが、シナリオA では subagent が自然解釈で正解に到達。構造的欠陥より「裁量許容範囲」寄り |
| FL-1-B-1（キーワード選定粒度） | subagent B が自発的に 5 分類へ拡張済み。裁量で正解に到達するため、明文化で肥大化するリスクが上回る |
| FL-1-C-1（解決方法の行数） | 軽微な書式問題。実用上は 1 行要約で合意形成済み（subagent C が自己判断） |

## 次の修正案

SKILL.md L93-95「参照完了時は以下を出力する」ブロックに、`[件数]` の定義を 1 行追記する:

```
📋 履歴確認済み: [件数]件の関連失敗を確認。除外手法: [手法名]
```

↓

```
📋 履歴確認済み: [件数]件の関連失敗を確認。除外手法: [手法名]
※ [件数] = 関連キーワードでヒットした全エントリ数 (解決済み含む)、[手法名] = そのうち未解決エントリの「試した手法/コマンド」欄に記載された手法 (カンマ区切り)
```

1 行追記で、`[件数]` / `[手法名]` 両方の曖昧を同時解消。波及上振れで EP-1-B-1 も消える。
