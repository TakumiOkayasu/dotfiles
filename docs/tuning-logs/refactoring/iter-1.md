## 次の修正案

### 採用テーマ: **委譲先節の新設**

**修正内容**: SKILL.md「禁止事項・制約」表の直後に短い節を追加（3-5 行、新節）:

```markdown
## 委譲先（範囲外作業）

| 範囲外作業 | 委譲先スキル |
|---|---|
| テスト新規作成・特性テスト追加 | tdd |
| バグ修正・原因分析 | systematic-debugging → tdd |
| 新規 interface 設計 | interface-first-design |

委譲時は「本スキルの対象外」を明示してから委譲先を提案する。
```

**根拠**:
- R-0-2 / R-0-4 / R-1-B-1 / R-1-B-2 / R-1-C-1 の 5 件が **同一構造（隣接スキル委譲のフォーマット未規定）** に集約 → 1 修正で複数潰せる（empirical-prompt-tuning「修正の波及パターン」上振れ期待）
- シナリオB (テスト不在 → TDD)、シナリオC (バグ混入 → sd/TDD)、hold-out D (新規実装 → iface-first) を全カバー
- 修正サイズ最小（新節 7-8 行のみ、既存節への影響なし）

### 不採用テーマ
- **R-1-A-2 / R-1-C-2 (マジックナンバー定数化境界)**: 2 シナリオで観察されたが両方とも subagent が「分離」「値据え置き」で正解動作。明文化の追加価値は委譲先節より小さい。iter 3 以降に温存
- **R-1-A-1 (テスト実行環境不能時の代替)**: SKILL.md は人間 / agent どちらでも適用前提のため、agent 環境特有の補足は冗長化リスク。iter 3 以降
