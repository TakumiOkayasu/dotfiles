## 鉄則保持の実地観察

- **冒頭で「対象外」を断言**: 「本依頼は refactoring スキルの対象外です」と明示
- **判定表 3軸**（既存コード構造改善か / 振る舞い不変か / テスト前提条件）すべて「×」で機械的判定
- **委譲先表を直接引用**: 「新規 interface 設計・新規実装 → interface-first-design」を行ごと引用
- **description 全文を太字引用**: 要件5 を完全充足
- **5ステップ順序提案**: 「疑似コード→interface→クラス→TDD→実装」を委譲先スキルの定義順序として正確に列挙

iter 2 で追加した委譲先表 + iter 3 で追加した境界節が **誤発動の構造的ガード** として機能。SKILL.md 本体の手順（フェーズ1-5）に進む前に description / 委譲先表で振り分けが完了する設計が hold-out で実証された。
