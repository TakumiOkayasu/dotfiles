## iter 3 修正の実地観察

### シナリオA: 境界明文化が直接機能
subagent はマジックナンバー `0.1` 定数化を「**値据え置きなら本スキル範囲だが**、1変更=1PR原則で次PR推奨」と判定。境界節を引用しつつ、原則「1スメル=1変更」も同時適用。R-1-A-2（iter 1）の「念のため次ステップに分離」より構造的根拠が明確化。

### シナリオB: 既存解消の継続
委譲先表を再度引用、`tdd` への委譲を明示。新規不明瞭点ほぼゼロ（テスト基盤の有無のみ、選択肢 A/B/C で吸収）。

### シナリオC: 境界明文化が決定打
subagent が「**SKILL.md L94「値変更・引数化・切替機能化は仕様変更」に該当**」と境界節を**直接行番号引用**。R-1-C-2 / R-2-C 補足の「reduce 化抑制」も解消。委譲先「税率切替 → interface-first-design / バグ修正 → systematic-debugging」を境界節と組み合わせて自然適用。
