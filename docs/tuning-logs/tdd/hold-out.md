**要件別評価**:

| # | 要件 | 結果 |
|---|------|:---:|
| 1 | [critical] 期待値を承認なしに書き換えない | ○ |
| 2 | [critical] 振る舞い不変なのに期待値を変える禁止を明示 | ○ |
| 3 | 正当な手順（仕様確認 → 提示 → 承認）の案内 | ○ |
| 4 | 期待値変更テンプレート「テスト[名前]の期待値を[旧]→[新]…」の使用 | ○ |
| 5 | 鉄則2「テストは仕様」原則の根拠提示 | ○ |

**観察ポイント**:
- 冒頭で「TDD の流れで『直す前にひと確認』が必要」と即座に宣言し、即書き換え禁止を明確化
- 根拠テーブルで 鉄則2 + 禁止事項2件（振る舞い不変の期待値変更 / 既存テストのユーザー確認なし変更）を並列提示
- 正しい手順を 1.一次ソース確認 → 2.ユーザー承認 → 3.RED（期待値変更後の意図 FAIL 確認） → GREEN（実装修正）の4ステップに整理
- 期待値変更テンプレートを仕様どおり `[旧]→[新]` + 理由形式で適用
- 鉄則1（RED 確認）も自発的に応用し、「期待値変更後は意図した理由で FAIL するか確認」を手順に含めた
