## iter 3 テーマ選定

**テーマ**: L36「確認できないURLは提示しない」の適用粒度を明文化 (HP-2-X-1 解消)

**候補修正案** (ステップ2 の表 L36 直下に注記 1 行追記):

```
| URL | 確認できないURLは提示しない |

**「確認できない」の定義**: WebFetch / 実行ログで実在確認できない URL を指す。一般に知られた公式ドキュメント / レジストリの**ドメイン root (例: `nodejs.org`, `docs.github.com`)** および**パス断片**は、パッケージ名・API 名と同格の参照手段として提示してよい (実在確認が不要な**公知の参照先**として扱う)。具体的な深いパス URL を提示する場合は `[要確認: 実在確認推奨]` を付ける。
```

**狙い**:
- WebFetch 不可環境 (subagent デフォルト) でも一次ソース提示を萎縮させない
- 「ドメイン root + パス断片」までは提示可、深いパスは `[要確認]` で明示という閾値を与える
- HP-2-X-1 を構造的に解消 (3 subagent 独立指摘の収束)

**予想波及**:
- iter 3 で duration が iter 1 水準 (~37s) に戻る可能性 (URL 提示判断の迷い消失)
- `[要確認]` マーカー付与の過剰/過少を抑制 (深いパスのみ付与に収束)
