## 懸念点 (iter 1 で検証する候補)

### IP-0-1: L28 ロギング必須 vs L55 「本番コード」スコープ不整合 (hold-out D 直撃、最有力)

- L28 (必須経由表): 「ロギング: ロギングライブラリ経由。`print` / `console.log` / `echo` の直接使用禁止」 — **無条件**
- L55 (禁止事項表): 「`print` / `console.log` 等の直接使用 (**本番コード**)」 — 本番限定
- **矛盾**: 同内容で scope が食い違う。subagent が L28 を優先すると hold-out D (個人ワンショットスクリプト) でも print を拒否 → 誤発動
- iter 1 D で主因化する可能性が最も高い

### IP-0-6: 暗号学的乱数 (CSPRNG) への明示的言及なし (baseline C 直撃、高)

- L11: 「再発明禁止対象」に「乱数」が混在 (汎用乱数扱い)
- L30 / L52: 「暗号・ハッシュ」自前実装禁止のみ (乱数は暗号ではなく別カテゴリ)
- **欠落**: 暗号学的乱数 (`secrets` / `crypto.randomBytes`) と通常乱数 (`random` / `Math.random`) の区別なし
- baseline C (パスワードリセットトークン) で `random` / `Math.random` を subagent が提案するリスク

### IP-0-7: ORM 例外の判定フロー不明 (baseline B 直撃、中)

- L34-46: 許可シナリオ一覧 + 共通条件のみ
- **欠落**: 「どの順で判定するか」の手順 (まず ORM で書けるか → 表現困難なら根拠を示す → プリペアド必須 → レビュー付帯)
- subagent が許可条件をざっと眺めて「生 SQL 可」と短絡する恐れ (B で critical 1「判定する」が抜ける)

### IP-0-4: 「監査可能な形でコミット」の具体性不足 (B 影響、中)

- L46: 「監査可能な形でコミット (レビュー対象として明示)」
- **曖昧**: 何をすれば「監査可能」か未定 (コメント? PR 本文? 両方?)
- L46 直後の「理由をコメントまたは PR 本文に記載」で補完されているが、subagent 解釈次第でスキップ

### IP-0-5: 設定値外部化の選択基準未記載 (baseline A 影響、中)

- L32: 「環境変数**または**設定ファイルで外部化」
- **欠落**: 秘密情報 (API キー / パスワード) と非秘密設定 (タイムアウト / バックオフ係数) の使い分け基準
- baseline A (バックオフ係数 / タイムアウト) は「どちらでもよい」が正解、C (有効期限 30 分) は非秘密だが外部化対象、秘密鍵があれば env 限定 — subagent の判断が割れる可能性

### IP-0-2 (残置候補): L9「既存優先」と L17「追加前確認」の重複

- L9 (基本原則) + L17 (依存管理) に同趣旨 2 箇所
- **残置理由**: 重複は冗長だが矛盾ではない、subagent 実害は低い。修正すると rule 肥大化

### IP-0-3 (残置候補): L10「承認を得る」の主語不明

- L10: 「『なぜ既存で不可なのか』を明示し承認を得る」 — 承認者不明 (レビュワー? ユーザー?)
- **残置理由**: rule としては「明示する」行為が実行されれば目的達成、承認者の明文化は運用側の話

### IP-0-8 (残置候補): バリデーションとシステム境界の紐付け

- IP L29 「入力検証は定評ライブラリ」、CC L211 付近 「システム境界で実施」
- **残置理由**: 責務分離 (IP = ライブラリ選定 / CC = 位置) で棲み分け可、subagent 混乱は小

### IP-0-9 (残置候補): 「読み取り専用レポート」の判定基準

- L41: 「読み取り専用レポート」許可条件
- B (月次集計→CSV 書き込み) が「読み取り専用」に該当するか自明ではない
- **残置理由**: B の critical 項目 (プリペアド / 複雑集計判定) に直接影響しない、許可シナリオは他項目でカバー
