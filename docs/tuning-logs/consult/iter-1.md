## iter 2 テーマ選定

**候補比較**:

| # | テーマ | 因果の明瞭さ | 修正コスト | 波及性 |
|---|---|:---:|:---:|:---:|
| C-1-B-1 | 関連スキル・境界節を新設 | ◎（要件3「部分的」の直接原因） | 低（10行追加） | ◎（refactoring iter 2 と同型、上振れ期待） |
| C-1-A-1 | 「スマホ・PCクライアント」の意味明示 | ○（実害は軽微） | 低（役割分担表の補足1行） | 低 |
| C-1-B-3/C-1 | 「AとBで迷う粒度」基準明示 | ○（2 subagent で独立報告） | 中（前提条件節の再構成） | 中 |

**選定**: **C-1-B-1（関連スキル・境界節の新設）**

- 理由:
  - シナリオB の要件3「部分的」判定の直接原因で、因果が明瞭
  - refactoring iter 2「委譲先節新設」と同型パターン（empirical-prompt-tuning「修正の波及パターン」上振れ事例）
  - iface-first 境界明示は trigger-overlap.md で 🟡 中リスクと事前特定済
  - 追加のみの修正で他シナリオへの負の副作用リスク低

**修正案**（iter 2 で実施）:

```
## 関連スキル・境界（発動前の判断）

本スキルは「判断の相談」に特化する。以下の隣接領域は別スキルに委譲する:

| 状況 | 委譲先 |
|---|---|
| 新規 interface 設計・責務分割・依存関係整理 | `interface-first-design`（疑似コード→interface→クラス→TDD） |
| バグの原因分析・仮説構築 | `systematic-debugging`（Phase 1-4、「なぜ?」3-5回） |
| 繰り返す失敗の記録・再発防止 | `failure-logging` |
| テスト駆動の実装 | `tdd` |

「AとBで迷っている」レベルまで絞り込めていない場合は、本スキルを発動せず上記スキルへ誘導する。
```

**配置**: 「前提条件」節の直後（L30 の後）。発動判断フローで「トリガー → 関連スキル確認 → 前提条件 → Phase 1-4」と自然に読めるため。
